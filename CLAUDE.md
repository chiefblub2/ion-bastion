# CLAUDE.md

Notes for agents working on ION BASTION. The player-facing overview (rules, controls, multiplayer usage) is in README.md; per-mission, tower and enemy details live in the game's Sector Atlas and codices, not in the README.

## Stack and commands

TypeScript (strict, ESM), Phaser 4.2, Vite 6, Vitest 3, `ws` for the relay. Node 22+.

PNGs under `assets-src/` and `public/assets/` live in Git LFS (`.gitattributes`); new art there is picked up automatically. A checkout without `git lfs pull` has pointer files instead of images, which breaks the art audits and the game's sprites. The Pages workflow caches `.git/lfs/objects`.

Always run `npm test` and `npm run build` before you finish. When missions, waves, enemies, towers or strategies changed, also run `scripts/balance.ts` for the touched sectors (it is the only check that strategies A/B win and weak defenses lose). Skip it for new towers: the strategies never build them, so the run only repeats the baseline. The chunk-size warning from `vite build` is expected.

To see a change in the real app, run `npm run dev` (and `npm run server` for multiplayer) and open `http://localhost:4173`. Use `?server=ws://host:port` to point at another relay, and `?mission=<id>` (e.g. `?mission=korallengraben`) to open a mission directly; `&wave=<n>` starts it at wave n (the remaining waves keep their real HP; the HUD counts from 1). `&credits=<n>` replaces the starting credits. Without a valid `?mission=` the app opens on the start screen. `app/screens.ts` switches two views in one document (`<html data-view="menu|game">`, `#start-screen` / `#game-view`) through the History API: `/` is home, `/#missionen`, `/#mehrspieler`, `/#gegnerakte`, `/#turmakte` (Tower Codex, `ui/tower-codex.ts`; its icons are the README images in `docs/images/towers/`, bundled via `import.meta.glob`, glyph fallback), `/#spielhilfe` are its pages (the former dialogs, same element ids), `/?mission=<id>` is the game. Leaving the game pauses a solo wave and coming back resumes it; the battlefield refits on return (`Battlefield.fit`). Persisted data, all in localStorage: the last mission id (`app/progress.ts`), which only ever offers "Restart Last Mission" from wave 1; the campaign record (`ion-bastion:campaign`, also the only source of the campaign unlocks, best 1–3 stars per won mission id stored as `{ v, stars }`, the bare legacy map still reads; read by the atlas through `AtlasOptions.record`); the sound settings (`audio/settings.ts`, key `ion-bastion:sound`); and the graphics settings (`render/graphics-settings.ts`, key `ion-bastion:graphics`: the Bloom switch in the sound panel, off by default on a coarse pointer). Stars come from the pure `missionStars` (`app/rating.ts`: reactor energy left, or on circle missions the fullest the ring got, followed render-side by `PeakTracker`). The `main.ts` events hook records a win only outside versus and only for the unmodified definition (`game.mission === findMission(...)`), so `&wave=`/`&credits=` runs never count; the win overlay shows the stars through `Interface.result`. The home page's primary button comes from the pure `homeAction` (`app/home-action.ts`: Start Playing / Resume Game / Restart Last Mission; a won or lost game is not resumable). Menu styles live in `src/menu.css` (tokens `--m-*`, scoped to `.start-screen`); the HUD stays in `style.css`. The mission page is the Sector Atlas (`ui/sector-atlas.ts`): a Campaign/Circuit mode toggle, then the world map (`#world-view`) with three zoom levels: the star system, one world, one sector. The worlds are display only (`ui/planets.ts`, `WORLDS`, split by `worldsOf`): the campaign's sectors in play order on three planets by each one's `count` (Vigil I–IV, Ashkar V–VIII, Thessaly Prime IX–XII; the last planet takes any beyond) and the Circuit on the moon Kepler's Ring, so Circuit sectors never share a world with the campaign. Each world places its sectors by hand (`centres` on the 200 × 100 plane; `planets.test.ts` fails when a sector has none), may hold one as a station in orbit (`station`: Orbital Deck floats above Vigil's horizon on a `deckOutline`, painted apart), and has its own unclaimed-land biome and atmosphere colour (`--atmo`). A world is seen from orbit, split by the pure `ui/world-map.ts` into territories (`planetLayout(centres, station)`: Voronoi cells plus a ring of unclaimed wilds; `jaggedBorder` warps every border point by position only, so neighbours share one jagged line; each `Region` has a `label` point; `fitBox`/`stationBox`/`planetBox` for the zoom, `HORIZON` for the planet's curve with stars and atmosphere above it). Missions follow a route shape per sector (`ROUTE_SHAPES`, picked by `routeShape` from the first map's theme, ring missions circle; `routePoints` turns it to the direction of travel, `headingOf`, inside the room `frameOf` measures); `routeLinks` draws the real unlock rule (each mission to the next, in the campaign a fainter skip link to the one after) and `asideOf` sets the restricted-towers mission off the route as a special op (diamond badge). Each territory draws its border clipped to itself in its state's colour (held, open, next, hostile = locked), so shared edges show both. The ground is painted by the pure `ui/planet-surface.ts` (`paintSurface`: warped value noise with ridged mountains, lit from the upper left, a `BIOMES` entry per `MapTheme` plus the wild biomes `waste`, `tundra`, `verdant`, `regolith`; biomes change at the drawn borders through the inverse border warp) in a worker (`ui/planet-worker.ts`, cached image URLs from `ui/planet-texture.ts`): a 512 px surface first, then a sharp tile of each sector zoomed into, then the full surface; until then each territory shows `biomeGround`. The SVG (`#world-svg`) sits on a plane that `fitWorld` scales and moves (a JS flight, `place` per frame), inside `#world-tilt`, which leans it back with CSS `perspective() rotateX()` (`tiltFor`; the layer is larger than the view with `contain: paint`, which Chrome's GPU compositor needs to paint the layers above). The sector labels (`#sector-tabs`, the page's sector tabs; the land itself is clickable too) and the stations of the selected sector (`#mission-list`, hex badges planted on stems) stay upright on flat layers above it, placed through `project` from their `data-wx`/`data-wy` world points. `#world-nav` along the lower edge steps to the world before or after. The zoom button (`toggleWorld`) steps out, sector → world → star system, and from the system back in; the system view (`#system-view`, `renderSystem`/`placeSystem`: a sun, orbits, each world a turning sphere of its own coarse surface with a ring of missions won, locked worlds as dark silhouettes, the moon around the last planet) fades over the world, and a world there (`data-planet`, `selectWorld`) lands on it whole with its next sector selected. The page opens on the selected sector's world and flies into the sector; `--inv` (1 / scale) keeps SVG line widths at screen size and `--px` sizes the dots; a ResizeObserver refits it. Below it sits one mission card (`.atlas-card`): the map in a fixed 3:2 frame (fitted whole, a blurred copy of the terrain fills spare edges, so nothing moves between missions), the briefing beside it with the one Start button at its bottom, level with the map's lower edge (fixed to the screen bottom on phones), and Intel across the bottom. Heights are natural; nothing stretches to fill the viewport. The campaign unlocks with progress, derived from the record alone by the pure `campaignLocks` (`app/campaign-unlock.ts`): the first mission is open; in an open sector a win opens the next two missions (so one hard mission can be skipped); a sector opens once `sectorGate` (all but one) missions of the sector before it are won; won missions and sectors holding one stay open, so older records lose nothing. Circuit, Training, the editor, Run, multiplayer (the lobby passes no `locks`), `?mission=` links and `?unlock=all` (QA, this page load) are never locked; the lock is menu-only and the simulation never sees it. Locked sectors (darkened territories with red borders) and stations (padlocks) can be browsed: the briefing shows `lockText` and a disabled Start; `selectMission` in `app/input.ts` sends a locked id to the atlas instead of loading it, `homeAction` and the overlay's Next mission only offer open missions, and the win overlay names what the win opened (`newlyUnlocked`, `Interface.result.unlocked`). Fresh unlocks flare once: `ion-bastion:campaign-seen` holds the ids the atlas has shown open (absent before the first visit, then nothing is fresh). The first open unwon mission of the mode (`atlasNext`) is marked NEXT and featured by default unless a game is under way (`AtlasOptions.playing`). The map and the card update on their own (`selectSector`, `selectMission`), and picking a mission never launches it. Mission previews are the real terrain (`drawTerrain`) rendered to image URLs by `render/terrain-snapshot.ts`: one lazily created canvas-renderer Phaser game, asleep between jobs, cached per map, with `mapPreviewSvg` shown until the picture is ready (and kept if it fails). The multiplayer page splits Create Room / Join Room / lobby in the UI layer only (`app/coop.ts`; `app/room-code.ts` has the code normalisation and the clipboard helper). Multiplayer needs several tabs, one per player.

The mission editor (`src/editor/`) is a hidden page: `/#editor` (`MenuPage` `"editor"`) ships in the production build but has no menu button, and `app/input.ts` lazy-loads `editor/editor-view.ts` (its own chunk) on entering it. `draft.ts` holds `EditorDraft`, its limits and the playtest id helpers; `codec.ts` turns a draft into a share link `?draft=<base64url JSON>#editor`; `storage.ts` keeps drafts in localStorage (`ion-bastion:editor-drafts`, current draft `ion-bastion:editor-current`); `wave-panel.ts` is the wave editor. Playtest sends the `playtest` command (`core/game.ts`, solo only: `playtest-solo` in co-op and versus, `playtest-invalid` for a mission that fails validation) with the draft as a `MissionDefinition` whose id carries the `playtest:` prefix (`isPlaytest`). Such a game is never recorded as a win and never remembered as the last mission, and the win/lose overlay and menu button return to the editor instead of the home page or atlas. Copy TypeScript (`export.ts`) emits a `parseMap(...)` const plus a mission literal: paste both into a sector in `content/`, then run `scripts/balance.ts` for that sector and add strategies as for any mission.

The Run mode (`src/run/`, page `/#run`, `MenuPage` `"run"`, home button `#menu-run`) is a solo roguelite: a full run is ten missions (three acts of two missions and an act boss, then the Final Stand), a short run act I only (`missionsOf`, `actsOf` in `map.ts`). Design and decisions: `docs/superpowers/plans/2026-10-24-run-mode-roguelite.md`. Everything in `run/` is pure except `storage.ts`/`session.ts`; all balance knobs live in `tuning.ts`. `rng.ts` (mulberry32 seeded through `fnv(stable([seed, ...key]))`, one stream per purpose, so offers and waves never shift each other; `seedText`/`parseSeed`, six base-36 digits). `acts.ts` (`actTiers`: the acts draw their source missions from the atlas planets via `worldsOf`, the Final Stand from the last two sectors). `map.ts` (`actMap(seed, act, …)`: derived from the seed alone, the run stores only `column`/`lane`; five columns of three lanes: missions, camps (`shop`, `forge`, `repair`, `event`), missions, camps, the act boss with its `BossModId`s; one lane of a mission column may be an `elite`; `nextNodes` joins neighbouring lanes; the column before the boss has a Shop or Repair in the middle lane). `state.ts` (`RunState` v2: `step` missions played, `act`, position, `phase` starter → map → mission/camp → reward → … act → … won/lost, `roster` (cap `rosterCap`, replacing at the cap drops the tower's XP and Doctrine), `relics`, `doctrines` (`<tower>:<path>`), `ranks` (XP per type), `mods` (Drill, discount), `scrap`, `reactor`/`reactorMax` (carried between missions; the mission's `reactorEnergy` is the run's reactor), `funds`, `loan`, `deployed`, `log`; the draft `towerOffers` weights by tab × shared `tags.ts` tags with a tower rarity per act and puts a counter first when `missingCounters` finds a need the coming nodes bring; `relicOffers`/`prizeOffers`/`legendaryOffers` by `Rarity`). `run.ts` (transitions: `newRun` (threat level rules from `ascension.ts`, unlockable fourth pack and trap pack), `chooseStarter`, `chooseNode`, `deploy`, `finishMission(run, MissionResult)` (a loss ends the run; a win carries the reactor plus `FIELD_REPAIR`, pays Scrap (stars, format, `hazardPay`), rank XP (kills plus `XP_BUILT`) and opens the reward: a draft, a relic every second win, the elite prize, a free Doctrine after mission 2), `pickTower`, `pickRelic`, `pickDoctrine`, `reroll`, `retire`, `continueRun` (after an act boss: the act transition with a full repair and a legendary relic or a Doctrine), `repairChoice`, `eventChoice` (`events.ts`), `abandon`); `shop.ts` (stock and `buy`). `generate.ts` (`runMission`: the source mission's map with a hot drop into `FORMATS[kind].enter` of its waves and `creditsAt` (its income up to there × `ECONOMY_SHARE`), resampled to the format's wave count and remixed: each group keeps its layer, its count × HP × √speed budget and its span but may swap its type within `enemyPool`, which keeps the needs the act allows (no stealth in act I) and drops what the roster cannot fight (`threats.ts`: `rosterCovers`, `needsOf`), and `airCap` grounds air groups beyond 35% / 60% of the budget with one or two anti-air attack towers; `hpMultiplier` is the source curve × `depthOf` (`DEPTH_HP` per act and column, elite and threat factors); boss modifiers (`boss.ts`) as pack, wave or remix changes; the pack is `runPack` (`lockSpecializations` for the Doctrines, mods, `rankTransform`s) then `applyRelics`). `transform.ts` has the shared pure pack transforms (`scaleStat`, `mapParam`, `discount`, `upgradePrice`, `lockSpecializations`), `relics.ts` 30 `RELICS` (content/mission transforms plus run-side fields `reactor`, `cap`, `xp`, `repair`, `flag`), `run-id.ts` (`run:<seed>:<step>` ids, `isRunMission`), `daily.ts` (date seed, threat 3, short). The `run` command (`core/game.ts`, solo only: `run-solo`, `run-invalid`) loads the mission with its own pack: `Game.content` is the active pack and `Game.baseContent` the constructed one, which every other load restores; its optional `replay` (`Replay`: commands with the `Game.ticks` they were applied at) re-applies a journal inside the command, so a reload resumes a run mission (`run/journal.ts`, `app/run-journal.ts`: every applied command is journaled with its tick and saved with `stateHash` after each command, every 300 ticks, at wave ends and on `visibilitychange`/`pagehide`). A deployed node can only be resumed; without a journal it counts as lost. `Game.ticks` counts effective ticks and is not part of the state. The simulation never learns about runs. `main.ts` builds the `MissionResult` (`app/run-result.ts`) and calls `settleRun` on the mission's `end` event (it only moves the stored run whose current mission id matches); run missions are never recorded or remembered, the HUD hides Restart, and the overlay and menu button lead to `/#run` (`ui/run-view.ts`, lazy-loaded with `ui/run.css`: intro with length, threat, seed, daily and history; starter; the act map with a node detail; deploy/resume card with threat chips; reward, camp and act screens; summary). After changing the generator, the relics, the acts or `tuning.ts` run `scripts/run-balance.ts`.

## Language

- Everything is English: code, comments, identifiers, these notes and all player-facing text (HTML in `ui/interface.ts`, texts in `ui/messages.ts`, `ui/players.ts`, `app/*.ts`, mode rules in `core/modes.ts`, content names, README.md). There is no i18n layer.
- The simulation returns language-neutral `MessageCode`s (`CommandResult.code`). `ui/messages.ts` maps every code to its text, and adding a code without a text fails `tsc`.
- Ids (mission, tower, enemy, map) stay as they are; only display names are English. The URL hashes `/#missionen`, `/#mehrspieler`, `/#gegnerakte`, `/#spielhilfe` and the map ids (e.g. `korallengraben`) are unchanged identifiers.

## Rules that must hold

- **All state changes go through `Game.command`** (or `Match.command` in versus). Each `HANDLERS` entry has an optional `allowedIn` status guard. Render and UI code only read state.
- **The simulation is deterministic:** fixed step `FIXED_STEP = 1/30`, no `Math.random`, no wall-clock time, and stable iteration order. Lengths use `len`/`dist` (`systems/path.ts`, `Math.sqrt`, correctly rounded in every engine), never `Math.hypot`; transcendental functions (`atan2`, `sin`, …) may differ between browsers, so their results must not drive simulation decisions (`Tower.angle` is render-only and left out of `stateHash`). Multiplayer relies on it; `net/lockstep.test.ts` compares state hashes across clients every frame. The only randomness is `roomCode` on the server.
- **Graphics never change the simulation.** Events (`GameEvent` union) are drained after each render frame. Render-side memory (`render/trails.ts`) only reads the state.
- **Solo play is the baseline.** New optional fields on state, enemies or spawns must stay `undefined` in solo, so solo state and balance stay unchanged (example: `sentBy`).
- **Content is separate from runtime instances.** Upgrades never mutate definitions, and `Tower.upgrades: string[]` is the only source of upgrade progress.
- `Game` accepts its own `ContentPack` (`new Game(mission, content)`). Pure queries (`resolveUpgrades`, `effectiveTowerStats`, …) take `content` as the last, optional parameter. `resolveUpgrades` is cached per content pack and upgrade list.

## Sound

- Render side only: `app/audio.ts` reads the drained events once per frame (`Audio.frame`) and never changes state. `audio/cues.ts` turns the few events that are effects (heavy blasts, kills, tower actions, flow and alerts) into cues. Shots go to the shot mixer instead (see below). A new `GameEvent` type gets a cue there or stays silent on purpose.
- Recipes are ZzFX parameter arrays (`audio/recipes.ts`), tuned in the ZzFX designer and on `/gallery.html?sound`. `zzfx.ts` is a port of ZzFX's `buildSamples` (the npm package creates an `AudioContext` on import); randomness is applied as playback-rate jitter. Shot recipes stay tonal or low-passed: a positive ZzFX `filter` (high-pass) on noise is hiss, and `recipes.test.ts` rejects it.
- **Towers never feed the music.** They have build, sell and upgrade effects and one quiet shot transient per family (`families.ts`). `audio/shots.ts` (`ShotMixer`, pure) keeps a busy field pleasant:
  - a per-family voice budget per real second (`BUDGET`);
  - a frame's shots of one family merge into one voice;
  - each voice's gain falls as 1/√(the family's voice rate), so the summed power stays about level from 3 to 40 towers (`shots.test.ts`);
  - pan comes from the tower's column, and each tower type keeps a stable pitch offset (`rateOf`).

  Shots play on their own sub-bus in `engine.ts`, with a high shelf that closes with the shot density (`shotDensity`) and a gentle compressor.
- **Music** is a synthwave soundtrack driven only by game state. `Conductor` (`conductor.ts`) takes a `Measure` from `intensity.ts` (read-only, every 0.5 s, never reads towers). **Currently off in the game:** `MUSIC_ENABLED` (`audio/settings.ts`) is false, so `app/audio.ts` starts no sequencer and no pad and the Music slider is hidden; stingers, effects and UI sounds still play, and the sound board and `render-music.ts` still play the soundtrack. The conductor:
  - **phase:** menu, build, wave, paused, over;
  - **threat:** enemy weight × progress;
  - **danger:** front line² and reactor damage, or the crowd against the limit on circle missions;
  - **arc:** waves started / waves.

  How these drive the music:
  - Phase sets the arrangement. Menu: pad and a slow arpeggio. Build: pad, held bass and a soft arpeggio. Wave: the drum machine and bass build with the threat. Paused: pad only.
  - Threat, with a floor from the arc, sets the drums (`layersFor`: kick, gated snare, offbeat hats) and the bass line (`bassFor`: held whole notes, then 8ths, then the theme's `BassStyle`, then 16ths). The bass turns dissonant with the threat (`tensionOffset`).
  - At threat 0.85 or with a boss the music escalates: phrase marks (crash, riser, tom fill), 16th hats, and the theme's lead motif (`MOTIFS`).
  - Danger sets the mood colour: arpeggio direction and the pad's tension note.
  - Arc sets the chord size (`extentFor`) and opens the pad's filter.

  Supporting pieces:
  - `sequencer.ts` schedules 200 ms ahead on the audio clock ("A Tale of Two Clocks").
  - The engine drops a layer note more than 30 ms late instead of flamming. Stingers are never dropped.
  - `stingers.ts` holds the game's turning points (wave start and end, won, lost, boss), never tower actions.
  - Only sounds wait for the beat; the simulation never does.
- Sound palette (`instruments.ts`): one shared palette for every theme.
  - **Pad** (`ambience.ts`): two detuned saws per voice, a sub sine, a stereo chorus, and a filter re-strike on each chord change. No noise source.
  - **Instruments:** `synthBass`, `arp`, `lead`, FM `bell`, `swell`, and a Linn-style kit: `kick`, gated `snare`, `hat`, `tom`, `crash`, `riser`.
  - **Engine buses:** the pad and bass layers pump with every kick (`pump`, the sidechain). Arpeggio and lead feed a dotted-8th ping-pong delay (`tempo`). One darkening convolution reverb is shared.
  - **Voice handling:** panners are cached per destination and position, voices free their nodes `onended`, and `MUSIC_VOICES` caps all music notes.
- Themes differ by key, tempo, mode, progression and groove (`MUSIC` in `harmony.ts`) and by a `PadFlavor` in `audio/drones.ts`: cutoff, spread, chorus, breath, sub, bass style, lead motif. A new `MapTheme` needs both (`tsc` enforces it).
- Towers pulse on the beat through the battlefield hook `pulses`. `Conductor.ages` gives the time since the last kick (or quarter note) for every family, in a wave only.
- No `AudioContext` before a gesture: a saved "on" starts on the first pointer or key press (`armAutoStart`); a hidden tab suspends the context.

## Rendering

- **Layers** (`scene.ts`), bottom to top, with explicit depths from `DEPTH` (`render/depths.ts`): terrain (baked), `ambient`, `hints` (build-mode cells, coverage overlay), `towerInk` + `towerGlow` (plus a `ghost` of the trap being placed), `enemyUnderlay`, `enemyBody`, enemy sprites, `enemyOverlay`, `ink` + `glow` (selection ring, shots, effects, portal pulse), income labels. Objects created mid-game (sprites) must set a depth; equal depths keep creation order. The glow layers blend additively and sit above their ink. Tower light lies below the enemies, so units and health bars are never lit.
- **Terrain** (`terrain.ts` `drawTerrain`, drawn once per mission): ground from `ground.ts` (smooth value-noise tone instead of a hard checkerboard, soft patches, a material grain per `GROUND_FAMILY` of the theme, contact darkening along obstacles and the path, and a bevelled pad on every buildable cell), decor at 0.7 alpha, a soft `contactShadow` (`landmark-art.ts`) under every obstacle, landmarks, the path with depth (cast shadow, lit and shaded lip, sunken bed, worn lanes, grit) and a material per ground family (`path-material.ts`: seams, ripples, cracks, …, worn corners and ends), entry and reactor, `drawBoardLight` (light pool from the upper left, smooth edge falloff, bevelled rim) and the labels. `drawTerrain` returns its objects; `Battlefield.bakeTerrain` draws them, hidden, into one RenderTexture at the camera zoom (re-baked when the zoom changes), so terrain detail costs nothing per frame. New randomness uses salted seeds (`groundRandom`, `hash01`), so the themes' own `cellRandom` rolls stay unchanged. **Obstacle pieces:** `obstaclePieces` (`obstacle-pieces.ts`, pure) splits the obstacle cells outside landmarks into pieces; in groups, about `BIG_SHARE` of the free 2×2 blocks become one piece drawn as the theme's own `obstacle` at twice the size (`enlarged` in `terrain.ts`: `save`/`translateCanvas`/`scaleCanvas`), so groups mix big and small obstacles in the theme's style. Their ambient runs once more per big piece under the same transform with `path: []` and a board of size 0, so only its obstacle part draws (a theme ambient must tolerate an empty path). **Landmarks:** `landmarkSpots` (`landmarks.ts`, pure) picks up to two 2×2 obstacle blocks, else single obstacle cells with the most obstacle neighbours, each with a hashed `variant`; `landmark-art.ts` draws one of two set-pieces per ground family there instead of the obstacles, and `landmarkLight` animates every one in `drawAmbient`. **Ambient** (`drawAmbient(g, glow, map, clock, still)`): theme animation on `ambient`, its light sources on the additive `towerGlow` (scaled by `themeGlow`); theme ambients loop `blocked` (obstacles without landmark and big-piece cells), never `map.blocked`; `hash` must stay the first `cellRandom` draw (it names the obstacle variant); reduced motion freezes it. `drawGates` draws the live entry portal and reactor core (red `alarm` near the end and after a leak). **Overlays:** with a trap armed and a cursor on the board, every path cell `canBuild` accepts gets a hint (cached per tower layout), the trap shows as a ghost and a blocked cell as a red ✕ (other towers keep the crosshair marker); hovering a built tower shows its range; `ViewState.coverage` (key C, `#coverage-btn`) draws every attack tower's range and a strip along the path from `pathCoverage` (`coverage.ts`, pure: red 0, amber 1, accent 2+ towers reaching ground units), shown dimmed while an attack tower is being placed.
- **Enemy stages** (`render/enemies.ts`): `enemyContext` is built once per enemy and frame; `drawEnemyUnderlay` (trait fields and trails, status rings, tentacles, then the shape's shadow), `drawEnemyBody` (the shape only, from `SHAPES[shape].body`) and `drawEnemyOverlay` (trait and status markers, HP bar; the shimmer of an unrevealed stealth unit) each draw one layer across all units. `drawEnemy` runs all three into one Graphics (gallery). Body art never draws its own shadow. **Enemy sprites:** `ENEMY_ART` (`render/enemy-art.ts`) maps an enemy id to a right-facing PNG in `public/assets/enemies/` (texture key; optional `scale`, the *visible* longest side in body diameters, default `ART_SCALE` 1.1, slender art ×`SLENDER_BOOST`; `angleOffset`; `shift`; `pose`) plus its measured visible `bounds` from the generated `render/enemy-art-bounds.ts` (`scripts/audit-enemy-art.ts -- --write`; `enemy-art.test.ts` fails when it is stale). `pose`: absent for top-down art (turned with the heading), `"profile"` for long side views (turned, mirrored instead of upside down when moving left; worms), `"upright"` for standing side or front views (never turned, mirrored left/right, keeping the last facing while moving up or down). `queueEnemyArt`/`sceneSpriteHost` (`render/enemy-art-scene.ts`) load and create them below the Vite base path for the battlefield and the art review page; `ART_FILTERING` (trilinear mipmaps, POT textures only) is in both game configs. `EnemySprites` (`render/enemy-sprites.ts`) keeps one Image per enemy id, reused across frames, placed by the pure `placeArt` (visible bounds centred on the position, the offset rotated and mirrored with the image; worm `shift` along the heading; `bodyLift` and hover), and `drawEnemyLayers` draws the procedural body only where `isRendering(id)` is false: no art, a texture that failed to load (warned once, never retried), a hidden stealth unit or a burrowed one. A sprite casts a rotated oval shadow sized from its visible footprint (`PAINTED_SHADOW`) instead of the shape's shadow. On WebGL every sprite also gets a light silhouette rim behind it (`RIM`: the same frame, slightly larger, fill-tinted, at `DEPTH.enemyRims`; the host opts in through `SpriteHost.rims`). HP bars (`drawHpBar`) are 4 px in three colour steps with the shield as a strip on top, hidden at full health without a shield except on bosses. Images are destroyed with their enemy, on a new game state and on scene shutdown. The gallery stays procedural. Painted bodies skip the procedural tentacles in the underlay. New or changed art: `scripts/audit-enemy-art.ts` (alpha, bounds, residue islands; `--fix` erases reviewed residue boxes losslessly), then `/gallery.html?art` via `scripts/enemy-art-review.ts`.
- **Enemy animations** (render only): `ENEMY_ANIMATIONS` (`render/enemy-animations.ts`) registers idle, move, hurt and death clips for every type the source manifest `assets-src/enemy-animations/manifest.json` enables (16 so far; the registry imports it, so the manifest is the only list; an entry may override clip fields per state, drop a state with `null`, or carry `disabled: "<reason>"` to keep a reviewed but unsuitable source out of the game), all from one grid sheet per type (`sheetKey`; a clip is a row: `start` frame plus `frames`, `sheetFrame` gives the Phaser frame); static art tuning stays authoritative (`animationArt` swaps in the cells' `ANIMATION_BOUNDS`). `queueEnemyAnimations` loads one spritesheet per type; the battlefield passes `missionAnimationTypes` (wave types plus split/brood offspring), so a mission loads only its own sheets (each decodes to 8 MiB) and releases the others on the next mission change (`sheetPlan`); the static art follows the same plan (`queueEnemyArt` with `missionEnemyTypes`, in the background from `create`, a unit stays procedural until its texture arrives); a type without a loaded sheet shows its static art. New sheets follow the project skill `.claude/skills/animation-pack/SKILL.md` (identity check before any rename, manifest entry, normalizer, audit and `-- --write`, review on `/gallery.html?anim` and in game; the first extra pack had ten sheets under each other's names). `EnemySprites` keeps one Image per enemy and sets the frame from `fxClock` via the pure `animate` (`render/enemy-animator.ts`: move/idle with hysteresis, one hurt clip per fresh hit with a gap, fallbacks move↔idle → static art → procedural); no Phaser animation definitions, so pause freezes everything. During a hurt clip the white flash is skipped. Deaths: `killedEnemies` takes only a `kill` event directly preceded by its victim's `damage` event at the same spot; `EnemySprites.retire` turns a visible animated body into a bounded (`MAX_DYING`) dying Image at its last placement. Codex previews (`ui/codex-preview.ts`) step the same sheets with `clipFrame` on a CSS background, one at a time, paused under reduced motion. DOM icons use painted art (`ui/enemy-art-icon.ts`) with the SVG as fallback. In dev builds `window.__enemySprites` exposes the manager for QA scripts.
- **Enemy feedback** (render only, never in the state, hash or network): `EnemyFeedback` (`render/enemy-feedback.ts`) reads the drained `damage` events (`consume`, the batch stays untouched) for bounded hit flashes and detects shield ripples from a falling `traits.shield` (a disruption reads 0 without a hit, so it never ripples); `observe` drops the state of enemies that left or whose id changed type. Times are on `fxClock` (stops while paused, same length at every speed). `enemy-appearance.ts` holds the pure tint priority (`resolveEnemyTint`: flash, stunned, burning, disrupted, slowed, vulnerable, faceted) and idle motion (`bodyMotion`); `EnemySprites.sync` applies them, a tint only when it changes. `drawEnemyAccents` draws the procedural hit highlight, the shield ripple and at most two status accents on `enemyOverlay` under the markers and HP bar; hidden and burrowed units get none. Phaser's canvas renderer ignores tints (headless Chrome uses it unless started with SwiftShader WebGL), so then the overlay draws the hit highlight on sprites too (`SpriteHost.canTint`). `themeGlow(map)` dims both glow layers on light ground. Draw functions take a `Pen { g, glow }`. Phaser 4 notes: tint colour and mode are separate (`setTint(c).setTintMode(FILL)`; `setTintFill` is a silent no-op), a RenderTexture draws only on `render()` (`bakeTerrain`), `Graphics.fillPoints`/`strokePoints` accept plain `{ x, y }` through `render/phaser-points.d.ts`, and the canvas renderer (atlas snapshots in `terrain-snapshot.ts`) is deprecated but still works.
- **Primitives:** in tower, projectile and effect code use `disc`, `ring`, `arcBand`, `wedge`, `oval`, `chamferRect` and `strip` from `shapes.ts`. Don't use Phaser's `fillCircle`, `strokeCircle`, `arc`, `slice`, `fillRoundedRect` or `fillEllipse`: Phaser splits every arc into 100 segments, however short (a dash of a dashed ring too). Where the current fill or line style is already set (enemy markers), `fillRound`, `strokeRound` and `arcPath` (between `beginPath` and `strokePath`) replace `fillCircle`, `strokeCircle` and `arc` one for one.
- **Baked tower bodies** (`render/tower-bodies.ts`): `drawTower` is a still body (shadow, `BASES`, collar, r14 ring) plus a live top (glint, motif, lamps, turret, level bars, badge). `TowerBodies` bakes the body's ink once per `bodyKey` (type, level, colour, maxed, path) into a DynamicTexture at 2× the camera zoom (a texture has no MSAA) and shows one Image per tower at `DEPTH.towerBodies`; `drawTower(…, baked)` then draws only the body's light. `stillBody` decides per key by drawing the body twice with different time, id, cooldown and angle: a base whose ink moves (Inferno's vents, Aura, …) stays live, so a new base needs no registration, but keep metal that animates on `glow` where you can. Textures follow the zoom (`setZoom` re-bakes) and are dropped when no tower shows them. The badges (level, colour, path, aura boost) are memoised per tower in `Battlefield.towerLooks` and rebuilt only on a build, sale or upgrade.
- **Screen effects** (`render/screen-fx.ts`, WebGL only, behind the Bloom setting): `Phaser.Actions.AddEffectBloom` on `towerGlow` and `glow` (threshold pass off, the layers are light only), a red, desaturated camera `ColorMatrix` for 0.45 s on a `leak` (at most about once a second, the filter exists only while it runs) and a short camera shake on a `strike`; no flash or shake under reduced motion. Two Phaser 4 traps: ADD is (ONE, DST_ALPHA), so a filtered layer is primed with an opaque black rect (`ScreenFx.prime`) or stacked light adds up dim in the transparent framebuffer; and filter cameras zoom about the centre, so the board camera keeps the default origin and is centred with `centerOn` (with `setOrigin(0, 0)` the bloom drew offset).
- **Jitter** comes from `hash01` over positions, ids and time steps, never `Math.random`, so frames and screenshots repeat.
- **Lighting** (`material.ts`): light comes from the upper left (`LIGHT`, `facing`). Helpers: `plate` (bevelled plate with a sunken deck), `litBar` (metal bar), `dome`, `rivets`, `led`, `halo`, `glowLine`. Glow caps: one halo ≤ 0.3 alpha, white on glow ≤ 0.35; hot white cores are opaque fills on `g`.
- **Tower levels:**
  - L2 adds a collar and an LED.
  - L4 adds chasing LEDs and an inlay ring.
  - L5 echoes the r14 ring on glow and adds hot barrel tips.
  - L6–8 put the path colour on the trims and echo the motif on glow.
- **Turret aim** (`render/aim.ts`, `TurretAim`): `Tower.angle` changes only in the tick a tower fires, so the scene draws its own angle. In the last half of the cooldown a turret turns (`TURN_RATE`) toward the enemy `predictTarget` expects it to pick (the `attackEnemies` rules, read only: range, `canAcquire`, priority, taunts, the module's `choose`). When `Tower.angle` changes it snaps onto it, so no shot leaves a turning turret, and holds still until that last half, so a visible beam or flash stays on the barrel. Effects capture the angle when their event arrives; `Trails` starts follow it while a shot leaves the barrel.
- **Ground light and scorches:** `groundLight` (`effects.ts`) lights the ground on `towerGlow` under shots and impacts; `Scorches` (`render/decals.ts`) keeps up to `MAX_SCORCHES` marks of splash/mortar impacts and orbital strikes on `hints`, fading over `SCORCH_LIFE` on `fxClock`.
- **Barrels:** `MUZZLES` (`muzzles.ts`) holds the barrel length, recoil and parallel or fanned barrels per turret. Turret drawings, muzzle flashes (`muzzleTips`) and projectile starting points all read it.
- **Projectiles:** `Trails` (`trails.ts`) keeps per projectile id:
  - the start at the barrel tip;
  - samples for the trail;
  - the arc of point-aimed shells whose look sets `arc` (Mortar);
  - landed shots, which fade out instead of popping.

  The scene resets it when `game.state` is swapped (restart).
- **Effects:** each effect captures an `EffectOrigin` when its event arrives: the firing tower's level and angle, the landed shot's heading and blast radius.
- **Pulse, chain and beam looks** are picked by the source tower's `visual.turret`. It is found from the event colour, so base tower colours must stay unique; a shared colour falls back to the default look.

## Simulation details

- Order of `Game.tick` (only runs while `status === "wave"` and not paused): spawn, status effects, move, detection, projectiles, aftershocks, zones, attack, prune dead enemies, `settleWave`.
- Targeting follows `Tower.priority` (`TargetPriority`: first, last, strong, weak, close; set with `{ type: "target", id, priority }`). Absent means "first", the most path progress, and the handler deletes the field when "first" is chosen, so solo state stays unchanged. `compareTargets` (`systems/combat.ts`) orders candidates; ties fall back to path progress, then the stable id. An attack module's `choose` (Focus, Catalyst, …) receives the candidates in that order; Lance has none and fires at the priority target, piercing its line.
- Damage lands on impact. Projectiles are part of the state, fly at `projectile.speed` per tower, and still land after their tower is sold.
  - Homing shots (Pulse, Flak, Cryo, Catalyst) retarget within 1.5 cells when their target dies.
  - Nova rockets fly to a fixed point.
  - Tesla, Lance, Focus, Quake, Gravitron and Jammer hit instantly (`Impact.from`, `Impact.reach`). Quake centres its wave on `Impact.from`, the tower itself.
  - Shrapnel: a module's `volley` hook makes `attackEnemies` fire at that many different candidates per salvo, the chosen target first, then in priority order. Executioner judges its threshold on impact.
  - Mortar shells fly to a fixed point like Nova; its module's `minRange` hook makes `attackEnemies` skip enemies inside the dead zone.
  - Catalyst (`catalyze`) multiplies its hit by `1 + bonus × min(cap, activeEffects)` on impact (`activeEffects` in `systems/status.ts`: distinct running kinds, stun and pull only while they hold) and its `choose` picks the most affected candidate, priority breaking ties. Stabilizer lengthens effects through `prolongEffects` (never stun or pull).
  - Plasma (`pool`) shells fly to a fixed point and push a `Zone` into `GameState.zones` (absent while empty, hashed when present, cleared at wave end like `pending`). `tickZones` (`systems/zones.ts`) burns every `BURN_TICK` on a shared time grid as a dot via `canTarget` (so hidden and burrowed walkers burn, netted flyers too); pools of one tower never stack on an enemy in the same step. Eruption bursts through `blast(…, "pool")`, an area hit. The scene draws pools from the state (`render/zones.ts`) on `hints` with light on `towerGlow`. `pool` is a `CONTROL_KINDS` member, so Plasma sits on the Control tab.
  - Focus keeps its target through `choose` (which also receives the firing `Tower`) and stores its charge in `Tower.focus`, which is part of `stateHash`.
- **Roster:** 15 towers per tab (60). Mechanics added with the second roster, each in its own system file:
  - Orbital (`strike`, `systems/strikes.ts`): queued `GameState.strikes` (hashed when present, cleared at wave end) land `delay` s after the beacon on a fixed point; `landStrikes` runs between aftershocks and zones.
  - Mesmer `confuse` (walks backwards), Amber `encase` (`systems/encase.ts`: `speedFactor` 0, `deal` stores hits and the shatter deals them +bonus; drags, warps and knockbacks skip encased units), Magnetar `gather` (drags toward the target's path position, `clampToWall` stops it at Barricades), Cyclone (`pull` on air).
  - Tether (`systems/tether.ts`: slow/stun/burn spread once from `applyStatus`, `tetherStep` caps linked speed at the slowest partner still walking forward), Shrink Ray (`systems/shrink.ts`: `sizeOf` for Pitfall and Warp Pad, armor and `leakOf`), Hex `echo` (`systems/hex.ts`, stored in `afterDealt`, never re-echoed), Siphon (`systems/siphon.ts`, fire rate and Power Tap damage in `effectiveTowerStats` with `sim`, best value per stat).
  - Traps: Barricade `block` (`systems/barricade.ts`, `blockMove` in `moveEnemies`, `Tower.wall` hashed, restored after each wave; only real walkers), Warp Pad (`Enemy.warped`), Arc Plate (`chain` trap whose hops reach flyers), Oil Slick (`oiled` doubles burns, `systems/oil.ts`), Grinder `grind` (punishes standing still), Harpoon (`airTrap`).
  - Support (derived in `systems/support.ts` like the beacon): Overclock (window on the shared `state.time` grid), Fire Control (`Tower.critCount`), Armory (armor pierce in the armor trait), Skylink (`canTarget` for ground towers, `skylinkFactor` in `deal` scales only direct hits: dots, Recycler jumps and trap hits deal full damage), Nexus, Workshop (`systems/workshop.ts`, discounted price charged and recorded in `spent`), Vault and Shield Generator (`settleEconomy` in `settleWave` and the ring's `payWave`, before the wave bonus, `absorbLeak` in `moveEnemies`; the generator is dropped on circle missions), Recycler (`systems/recycler.ts`, one plain `overkill` jump; yields to Blood Transfer).
- Always deal damage through `applyDamage` (`systems/damage.ts`) and apply status effects through `applyStatus` (`systems/status.ts`).
- Status merge rules: for slow, burn and vulnerable, the stronger effect replaces the weaker one and an equal one extends it. Stun and pull (Gravitron) block further stuns or pulls until their recovery time ends. A pull is a negative speed factor, so it beats slow and stun; `moveEnemies` clamps `distance` at 0 on reactor maps. The stronger net (Snare Net) replaces a weaker one, and a disruption extends.
- `disrupted` (Jammer) hides the `DISRUPTABLE` traits (shield, regen, healer, leader, stealth, evade) from `traitsOf`, so every trait hook and `isHidden` follow it. `isHidden` also covers `burrow` (Burrower), which is stateless (derived from `distance`), not disruptable and not revealed by a detector; traps and area damage still hit. `netted` makes `canTarget` treat a flyer as air and ground.
- Passive support effects live in `systems/support.ts`: `bountyBonus` (Bounty Beacon, added to the kill reward in `applyDamage`), `markFactor` (Tracker, multiplied with `damageTaken` before armor) and `repairReactor` (Repair Dock, in `settleWave`). Like auras they are derived on every query and take the strongest overlapping tower. `availableTowers` drops `repair` towers on circle missions. Burn ticks every 0.5 s and credits the source tower even after a sale. Vulnerable applies before armor.
- Aura bonuses are derived from the current towers on every query, with no cache. Overlapping auras use the maximum bonus per stat. Cooldowns store the remaining fraction of a cycle, so a speed change never grants a free shot.
- Support towers are recognised by `aim: "none"` of their attack module (`isSupport`). They have no `targets`, no damage and no fire rate, are never buffed by auras, and only towers with an area (aura, detector, beacon, tracker) need a range. Their specs form `SupportAttack`, which `attackTower` excludes.

## Adding content

New towers need an icon for the Tower Codex: run `scripts/readme-images.ts -- --only towers` (it writes `docs/images/towers/<id>.png`). New missions or enemies only need `scripts/mission-table.ts --write` for the README intro counts.

Whole mission packs (new sectors, themes, enemies) follow the project skill `.claude/skills/mission-pack/SKILL.md`: foundation agent, parallel sector and theme agents, integration checklist. New enemies or traits for the existing campaign follow `.claude/skills/enemy-pack/SKILL.md`. Supplied enemy animation sheets follow `.claude/skills/animation-pack/SKILL.md`.

- **Training** (`content/training.ts`, `ContentPack.training`) is a guided mission outside `missions`, the sectors, the balance script and multiplayer; look missions up with `findMission`/`playableMissions` so it opens by id. Its `manualWaves` flag skips the wave countdown. The coach (`ui/coach.ts`, pure: steps derived from state plus acknowledged steps; `ui/coach-view.ts`, the `#coach` bubble and `ViewState.highlight`) only holds the wave start back in `input.execute` (`training-step`).
- **Mission:** add a `MissionDefinition` to a sector in `content/missions.ts` (or `content/sectors/*.ts`).
  - The fields are map, waves, `startingCredits` and `reactorEnergy`.
  - Optional: `hpGrowth` (default 0.14 per wave) and `availableTowers`.
  - `SECTORS` groups missions, and `MISSIONS` is the flat list derived from it; position determines the mission number. Validation checks that the sectors contain exactly `missions`, in order.
- **Map:** `parseMap(id, name, sketch, theme)` in `content/maps.ts`.
  - The ASCII sketch is the only source of truth: `S` entry, `R` reactor, `=` path, `#` obstacle, `.` buildable.
  - Size and path order are derived from it. Branches, dead ends and loose path cells are rejected with their coordinates.
  - A new terrain style needs an entry in `THEMES` (`render/terrain.ts`) and a value in `MapTheme`.
- **Circle mission (Circuit mode: the trailing sectors `circle.ts`, `gear.ts`, `tide.ts` in `content/sectors/`; every circle sector comes after all campaign sectors):**
  - A map sketch without `R` is a closed ring (`MapDefinition.loop`). `S` sits on the ring, and enemies leave it in the first free direction (right, down, left, up).
  - The mission sets `circle: { interval, limit, earlyBonus }`; validation requires `circle` and `loop` together.
  - `systems/circle.ts` replaces `settleWave`. The status stays `"wave"` from the first start to the end.
    - The timer (`state.circle.next`) starts overlapping waves.
    - `start` calls the next wave early for `earlyBonus` credits per second saved.
    - More than `limit` alive enemies loses; all waves started and an empty ring wins.
  - Overlapping spawns carry `Spawn.wave` for their HP scale. Versus rejects circle missions (`circle-versus`), so they run solo or in co-op.
- **Waves:** use the helpers `g(type, count, interval, delay)` and `wave(bonus, ...groups)` from `content/waves.ts`. An optional per-wave `hpMultiplier` replaces the linear growth.
- **Tower:** add it to `content/towers.ts`. Fields:
  - `attack`: kind plus values, e.g. `{ kind: "slow", factor: 0.55, duration: 1.9 }`
  - `visual`: `icon`, `turret`, `projectile`, `muzzle`, `impact`.
    - Projectile styles: see `ProjectileStyle` in `core/types.ts` (tracer, shell, crystal, twin, ember, glob, orb, net, rocket, lob, glaive, shard, vial, …).
    - A new look is one entry in `PROJECTILES` (`render/projectiles.ts`: body, optional trail and impact).
    - A new barrel is one entry in `MUZZLES`.
  - `targets`: the layers it can hit

  Menu, tooltips, detail values and validation are generated from the definition. The build menu has category tabs (Attack, Control, Traps, Support) once a mission offers `PAGED_FROM` towers; `pageOf` in `ui/tower-pages.ts` derives the tab from `placement` and the attack (traps, support towers, or `CONTROL_KINDS`). Menu order follows `towerOrder` (page by page). Hotkeys come from `hotkeyTowers(game, view.page)`: with tabs every tab numbers its towers from 1 (`TOWER_KEYS` in `ui/interface.ts`, 15 keys per tab; `t`, `f`, `n`, `c`, `m` and `u` are taken), and `Shift`+`1`–`4` (by `e.code`) opens a tab.
- **Trap:** use `trapTower` (`content/upgrades.ts`), which sets `placement: "path"` and keeps the trigger radius (`range`, about 0.45) at every level. Traps reuse the normal attack kinds.
  - `Game.canBuild(x, y, tower)` puts traps on free path cells (`isTrapCell`: not the entry and, with a reactor, not the reactor cell), everything else beside the path. The build fails with `trap-off-path`.
  - `attackEnemies` triggers traps with `canTarget` instead of `canAcquire`, so stealthed walkers set them off. Traps target ground only, so flyers pass over; the one exception is Harpoon, whose module sets `airTrap` (validation rejects air targets on any other trap). Skylink never widens what a trap can hit.
  - Trap-only kinds (`trapOnly` on the module, rejected elsewhere by validation): `bleed` (Caltrops: status `bleeding` costs `perCell` per cell walked, in `BURN_TICK` steps; standing or pushed back costs nothing), `charge` (Sticky Mine: status `charged` detonates at `until` or through the status `onDeath` hook, which `applyDamage` runs via `statusDeath`; a spent charge has `until = -Infinity`, so chains never repeat), `pit` (Pitfall: swallows enemies with `size` ≤ the spec and without `unstoppable` through an infinite hit, which `applyDamage` turns into the remaining HP) and `alarm` (Tripwire: sets `cooldown = 0` on attack towers in its radius, not on support towers or traps).
  - The scene draws traps flat (no shadow or turret rings) and suppresses their muzzle flash. A trap with `visual.impact` emits an `impact` event where it goes off.
- **Attack kind:** you need three pieces:
  - a module in `systems/attacks/` (`aim`, `projectile`, `params` with label, check and unit, `apply`)
  - an entry in `systems/attacks/index.ts`
  - a member of `AttackSpec` in `core/types.ts`

  Every `params` value can then be upgraded via `effects.attack` and shows up in the UI.
- **Status effect:** add a member of `StatusEffect` and an entry in `STATUSES` (`systems/status.ts`), with a merge rule and optional hooks.
- **Enemy:** add it to `content/enemies.ts`, with `layer` (`ground`/`air`), `visual` and optional `traits`. The available traits are armor, regen, splitOnDeath, slowImmune, shield, sprint, evade, healer, leader, stealth, unstoppable, swift, burrow, harden, surge, swarm, rage, facet, leap, dampen, brood, overload, molt, momentum, lap, refract, blastproof, insulated, heatshield, mirror, link, taunt, martyr, pack, cloakField, blink, tunnel, phase, blind, jam, defuse, suppress and retaliate. `momentum` raises speed with `distance` (a Gravitron pull takes it back); `lap` cuts damage per completed lap, `floor(distance / path.length)`, only on ring maps (always 0 with a reactor). `rage` raises speed with lost HP (`speed` hook); `facet` cuts non-dot hits in a window of the global `state.time`, so burn ticks and bleed pass while Decay (not a dot) is reduced. `leap` flips the layer in a distance window; `layerOf` (`systems/traits.ts`) is the current layer and `canTarget` uses it, so ground towers and traps miss a leaping walker and Flak misses a diving flyer. `dampen` (disruptable) makes it and enemies in its radius resist slow, stun and pull, checked in `resists`. `brood` (disruptable) lays its `type` every `every` cells (at most one per tick, never again after a pull-back); its count `Enemy.brood` stays `undefined` without the trait and is part of `stateHash`, and `tickTraits` iterates a snapshot so eggs tick from the next tick on. `overload` sets `cooldown = max(cooldown, cycles)` on attack towers (not support towers or traps) in its radius when it dies. `molt` reduces damage above an HP share and speeds up below it. Hit context: `applyDamage` takes an optional `Hit` (`systems/damage.ts`, built with `hitOf`: attack kind, `area`, `chain`, `instant`, source `tower`, Executioner `execution`); dots pass none. `refract` (instant hits), `blastproof` (area hits) and `mirror` (cap per hit, last damage stage; pit and execution pass) read it in `onDamage`, `retaliate` in `onHit`; `insulated` lives in the chain module. `link` splits a hit among same-type enemies in radius (shares cannot re-split, infinite hits are not split). `taunt` forces attack towers within its radius to pick it (`taunters` in `attackEnemies`, never traps). `cloakField` hides other enemies near it (`isHidden`, revealed by detectors, counted by `hasStealth`); `tunnel` extends `isBurrowed` with a speed bonus. `blink` jumps in `moveEnemies` (`blinkJump`, forward crossings only, clamped at the reactor). `phase` sets the layer from `state.time` in `layerOf`. `blind`/`jam` change attack-tower range/interval through the optional `sim` argument of `effectiveTowerStats` (`towerDebuffs`; previews without `sim` are unaffected), `defuse` stops traps (`isDefused`), `suppress` silences aura, detector, beacon and tracker (`isSuppressed`, not the dock). Area traits read their carriers from the incremental `withArea` lists in `systems/traits.ts`; none of them adds an `Enemy` field. DISRUPTABLE also covers link, taunt, martyr, cloakField, blink, blind, jam, defuse, suppress and retaliate. Enemies listed in `RESERVE_ENEMIES` (`core/mission-checks.ts`) exist but no mission uses them yet; remove an id when placing it (`core/missions.test.ts` checks both directions, and the README count skips them). A new trait is an entry in the `TRAITS` registry (`systems/traits.ts`), using the hooks `onDamage`, `onTick`, `onDeath` and `resists`. There is no inheritance tree and no global event bus. Stealth enemies and cloakField carriers may only appear in missions where the detector is buildable.
- **Upgrades:** `UpgradeDefinition` (`id`, `label`, `description`, `cost`, `requires`, optional `path`, `effects`) in `content/upgrades.ts`.
  - `attackTower` generates the five-level path.
  - `AURA_UPGRADES` defines the three exclusive aura paths.
  - Upgrades with different `path`s exclude each other on one tower.
  - Validation rejects duplicate ids, missing or cyclic requirements, and invalid costs or effects.
  - Every upgrade is bought with the same command, `{ type: "upgrade", id, upgrade }`.
  - `previewUpgrade` resolves a hypothetical purchase without changing state.
- **Specializations (levels 6–8):** `attackTower` appends three exclusive paths × three tiers from `content/specializations.ts` (`SPECIALIZATIONS` per tower id; ids `<slug>-<tier>`, tier I requires `level-5`, so a path may start from an upgrade without a path but never leave its path) and sets `visual.paths` (color, motif, name, role). Traps (`trapTower`) and support towers have none.
  - A tier holds final values: `effects.stats`/`effects.attack` as usual, plus `effects.specialization` (`SpecializationSpec` in `core/specialization-types.ts`, validated by `specializationError`), which `resolveUpgrades` replaces per tier.
  - `attackEnemies` snapshots it on `DamageSource.special` (and on the projectile), so it survives a sale; `hitOf` copies it to `Hit.special` for conditional damage (`deal`) and armor pierce (the armor trait). Secondary hits use `plain(src)`, so they never proc again. Fire-time procs travel as `Impact.proc` (Ricochet, Twin Arc via `Tower.specialShots`; Concentrated Volley). Overload's lone-target check happens at fire time.
  - `applyDamage` returns the primary `DamageOutcome` (Blood Transfer, Chain Reaction) and `applyStatus` whether the effect took hold (Brittle Ice, Compression, Weak Signal, Exposed Target; a rejected stun/pull merge is false). New status: `armorDissolved`; optional `stun.exposure` and `burn.spread`.
  - Aftershock waves queue in `GameState.pending`, fired by `fireAftershocks` between projectiles and attacks and cleared at wave end. `specialShots` and `pending` are hashed only when present.
  - `play()` never buys specializations, so the balance script ignores them.

## Tests

- Tests are pure Vitest with no DOM; they build a `Game` (or `Match`/`Room`) directly. Helpers in `core/test-helpers.ts`: `finishWave`, `play`, `makeEnemy`, `landProjectiles`. `play` lives in `core/play.ts` (no vitest import) so `scripts/balance.ts` can reuse it; the mission rules (air, stealth, buildability, thin defense, Nova-only, tutorial exemption) live in `core/mission-checks.ts` and are shared by `core/missions.test.ts` and the balance script.
- `core/missions.test.ts` keeps the campaign-wide content rules (ids, sector grouping, stealth only with a detector, every enemy appears). There are no golden replays or campaign simulations in the suite; mission balance is checked on demand with `scripts/balance.ts`.
- Keep tests lean: a few focused tests per new mechanic (the core formula, one edge, validation if it has params), no exhaustive matrices or snapshot tests.
- Multiplayer tests:
  - `core/coop.test.ts`: co-op economy
  - `core/match.test.ts`: versus rules
  - `server/room.test.ts`: seats and frames
  - `net/lockstep.test.ts`: N in-memory clients on one `Room`, asserting identical hashes every frame in every mode
  - `ui/players.test.ts`: HUD strings

## Multiplayer internals

- **Model:** deterministic lockstep through a relay that has no game logic.
  - `Room` collects commands and emits numbered frames, 30 per second, or two per tick at 2× speed.
  - The relay stamps each command with the sender's seat.
  - Clients apply each frame's commands in order, then call `tick()` exactly once.
  - Every `HASH_INTERVAL` (30) frames, clients report a hash, and the relay broadcasts `desync` on a mismatch.
- **Seats** are always `0..players-1` and double as wallet and field indices. When someone leaves, later seats move down (so a leaving host hands over seat 0) and the relay re-sends `room` messages. Leaving a running mission stops the clock, and the new host can relaunch. There is no reconnect and no late join.
- **Modes** (`core/modes.ts`, `MODES`): `coop`, `race`, `siege`, each 2–4 players. The host sends `launch { missionId, mode }`, the relay checks `fitsMode`, and every client gets `launched { missionId, mode, players }`. Frame 1 always contains the `mission` command.
- **Co-op:** a single shared `Game` with `setPlayers(n)`, driven through `coopSim(game)`. `earn` splits shared income and rotates indivisible remainders via `splitCursor`. Towers carry an `owner`. `hostOnly` and `ownTower` in `game.ts` guard restart/mission and sell/upgrade.
- **Versus:** a `Match` holds one solo `Game` per player, and every client simulates all of them. `fields[localSeat]` is the app's existing `game` instance, so the scene, HUD and dialogs render it unchanged.
  - **Commands:** `MatchCommand` adds `ready` and `send` to `Command`. `build`, `sell` and `upgrade` go to the sender's field. `mission` and `restart` are host-only and apply to every field. `pause` is rejected.
  - **Wave clock:** shared. The next wave starts on all alive fields when everyone is ready or after `READY_COUNTDOWN` ticks.
  - **Sends:** they go to the next alive opponent (`target`) and cost `sendCost` (4× reward). During a wave they are queued behind the target's current wave time; between waves they are buffered in `pending`. Sent enemies carry `sentBy` and pay no reward, and split fragments inherit it.
  - **Result:** a field with status `lost` is eliminated. The match ends with ≤1 survivor or when every survivor has status `won`. Ranking: alive, lives, elimination tick, kills.
  - **Events:** only the local field's events are drained by the scene, so `Match.tick` drains the others.
- **Adding a mode:**
  - Add an entry to `MODES`.
  - Put its rules in `Match` (versus) or behind the `Game` handlers (shared map).
  - Show its HUD in `ui/players.ts`.
  - Extend the parametrised lockstep test so every client stays in sync.
- **Desync safety:** `stateHash` walks the whole `GameState` (except `events`) through `stable`, so new state fields are hashed automatically (`core/hash.test.ts` checks the coverage). New per-match state on `Match` must be added to `Match.hash`. A detected desync stops the session on every client (`app/coop.ts`); the host can relaunch.
